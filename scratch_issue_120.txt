## Executive Summary
Tracks the development of the **Search, Discovery, and Emergent Folksonomy Layer** across the full ~4,000 cargo documents in Google Cloud Storage and PostgreSQL.

## Architecture: Micro Searchlight vs. Macro Sense-Maker
- **pgVector (cargo.content_vectors)**: Serves as a micro searchlight for point-queries inside an individual chase (matching a paragraph chunk against manuscript sections). It cannot provide a macro view of the collection.
- **Discovery Engine (Vertex AI Search) + Emergent Folksonomy**: Serves as the macro sense-maker and lit exhibition hall. Partitions thousands of unstructured documents into an empirical categorical lattice.

## Core Components
1. **Surface Mining (helper_scripts/inspect_cargo_landscape.py)**:
   - .00, zero-LLM frequency matrix extraction across all titles, abstracts, and publisher domains in cargo.content_metadata.
2. **Folksonomy Crystallization (helper_scripts/build_cargo_folksonomy.py)**:
   - Synthesizes 12–14 Level 1 Anchor Themes + ~50 Level 2 Folksonomy Tags (#tags) via Gemini 2.5 Flash (<.005).
   - Anchors the schema in cargo_ontology/fleet_folksonomy.json and cargo.system_glossary.
3. **Anchor & Expand Lifecycle**:
   - High-confidence classification for ongoing arrivals; low-confidence novel patterns buffered for Theme 15+ expansion audits to prevent schema drift.
4. **Interactive Exploration Visualizations (Streamlit cargo_discovery_console.py)**:
   - **Force-Directed Connection Network Map**: Visualizes thematic clusters, entity nodes (*Constellation Energy, Elsevier, Meta*), and cross-theme bridge articles.
   - **Spider / Radar Charts**: Corpus thematic balance and 13-Chapter manuscript alignment.
   - **Sunburst / Treemaps**: Hierarchical volume breakdown.
   - **Sub-Second Semantic Search**: Integrated with Vertex AI Search (
pt-cargo-search-app).

## 2. Answers to Grog's Architectural Questions

### Question 1: Storage of Folksonomy Tags in PostgreSQL
- **Recommendation: Hybrid Enrichment Pattern with High-Performance View**
  - **Ground Truth**: Commit analytical folksonomy events to `cargo.fleet_enrichments` (`enrichment_type = 'folksonomy'`, `payload = {'primary_theme': '...', 'tags': [...], 'confidence': 0.88}`). This strictly preserves **ADR-003** (clean provenance log of fleet enrichments).
  - **Query Performance**: Create a database view or materialized view `cargo.v_cargo_landscape`:
    ```sql
    CREATE OR REPLACE VIEW cargo.v_cargo_landscape AS
    SELECT 
        cm.id AS metadata_id,
        cm.title,
        cm.source_url,
        cm.publication_date,
        cm.publication_title AS publisher,
        cm.gcp_bucket_path,
        fe.payload->>'primary_theme' AS primary_theme,
        fe.payload->'tags' AS folksonomy_tags,
        (fe.payload->>'confidence')::float AS confidence
    FROM cargo.content_metadata cm
    LEFT JOIN LATERAL (
        SELECT payload FROM cargo.fleet_enrichments 
        WHERE metadata_id = cm.id AND enrichment_type = 'folksonomy'
        ORDER BY created_at DESC LIMIT 1
    ) fe ON true;
    ```
  - If query latency demands it, Hook can add a dedicated GIN-indexed `folksonomy_tags JSONB` column to `cargo.content_metadata`.

### Question 2: Manuscript 13-Chapter Alignment
- **Recommendation: Explicit Backbone Cross-Mapping**
  - Yes! In `cargo_ontology/fleet_folksonomy.json`, each Level 1 Anchor Theme must explicitly declare its **Primary Manuscript Anchor** referencing `ship/SHIP_DECK_PLANS.md`:
    - *Theme: AI Energy, Power Grids & Nuclear Restarts* -> **Chapter 4: The Alchemist's Bill**
    - *Theme: Academic Paper Mills & Peer Review Decay* -> **Chapter 5: The Guild Stenography Paradox**
    - *Theme: Scraping Lawsuits & Copyright Fair Use Collapse* -> **Chapter 7: The Enclosure of Knowing**

  - This powers the **13-Axis Manuscript Spider/Radar Chart**, allowing Bilgeladle and Timothy to see which book chapters have the deepest empirical reinforcement in the hold.

### Question 3: Graph Visualization Tech Stack
